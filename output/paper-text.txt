ABSTRACT
Network Function Virtualization (NFV), as a fundamental enabler of Mobile Edge Computing (MEC), facilitates 
the decomposition of monolithic network services into modular components. These components are organized as 
Service Function Chains (SFCs) in MEC-enabled Internet of Things (IoT) networks, where Virtual Network 
Functions (VNFs) are arranged in a predefined order to ensure efficient service delivery. The key challenge lies in 
optimal SFC placement, where end-to-end latency often increases linearly with the length of SFCs. While 
Network Function Parallelism (NFP) mitigates latency by enabling parallel processing of packets across multiple 
VNFs, the combined effects of fairness in resource competition and the benefits of VNF sharing have been largely 
overlooked. To address this gap, we propose a Fairness-aware and Parallelized SFC Placement framework with 
VNF Sharing (FPPVS), formulated through deep reinforcement learning. FPPVS identifies interdependencies 
among VNFs to reconstruct traditional SFCs into partially parallelized configurations, while ensuring latency 
constraints are satisfied. Moreover, it ensures fairness in resource allocation while leveraging VNF instance reuse 
for future requests, taking into account latency effects caused by resource contention. Extensive simulations show 
that FPPVS achieves lower average latency and higher resource efficiency than existing methods.
1. Introduction
The rapid proliferation of Internet of Things (IoT) applications has 
placed unprecedented demands on network infrastructures, necessi -
tating innovative paradigms to ensure efficient resource utilization, high 
reliability, and low latency [ 1 ]. In order to achieve strict service re -
quirements, Mobile Edge Computing (MEC) has become a crucial 
enabler in this environment, bringing computing and storage resources 
closer to end users. However, the adoption of more adaptable and 
economical methods is encouraged by the substantial capital costs 
(CAPEX) and operational expenditures (OPEX) associated with estab -
lishing standard network topologies in MEC contexts [ 2 – 4 ]. By sepa -
rating network services from specialized hardware and facilitating their 
deployment as modular, software-based components, Network Function 
Virtualization (NFV) has emerged as a crucial technology to achieve 
MEC. NFV makes it easier to deliver MEC services at a lower cost, in -
creases scalability, and improves adaptability by virtualizing network 
capabilities into Virtual Network Functions (VNFs). Representative 
VNFs include Intrusion Detection Systems (IDS), Deep Packet Inspection 
(DPI), Load Balancers (LB), Firewalls (FW), and Network Address 
Translation (NAT), among others [ 5 , 6 ].
To guarantee orderly packet processing and smooth service delivery, 
VNFs are typically arranged into Service Function Chains (SFCs). In 
order for traffic flows to reach the intended Quality of Service (QoS), an 
SFC specifies a certain order of VNFs, which is frequently dictated by 
application requirements [ 7 , 8 ]. Deploying ordered VNFs onto physical 
nodes and creating the required connections while meeting latency and 
throughput requirements constitute the SFC placement problem. Despite 
the advantages of NFV, resource constraints and heterogeneity in MEC 
nodes, dynamic and massive IoT traffic, and the intrinsically sequential 
structure of SFCs that worsens end-to-end latency make optimal SFC 
placement in MEC-enabled IoT networks extremely difficult [ 2 ]. Addi -
tionally, equitable resource distribution is crucial, and VNF sharing 
complicates placement choices.
As the number of VNFs in an SFC increases, end-to-end latency grows 
due to sequential processing at each VNF [ 1 ]. Processing latencies can be 
greatly decreased by sharing existing VNF instances during SFC assem -
bly, which reuses resources rather than creating new ones. By identi -
fying shared VNFs and rerouting traffic to instances that are already 
operational, this method lowers the overhead associated with deploying

complicated by network dynamics and intricate request patterns [ 10 ]. 
Resource management techniques and fairness principles are crucial for 
maintaining QoS in order to avoid congestion and excessive latencies 
brought on by competing flows when sharing VNFs [ 11 ]. As a result, 
VNF sharing might not always provide the best answer for the current 
SFC request.
Adoption of NFV can be incorporated with little disturbance and 
does not require a total redesign of network infrastructure. However, the 
abstraction layer that is added between VNFs and hardware results in 
extra overhead, which lowers performance and increases delay. End-to- 
end latency increases linearly with the number of VNFs in an SFC [ 1 – 3 ], 
and VNF processing generally stays slower than hardware-based 
implementations even with enhancements like Data Plane Develop -
ment Kit (DPDK) and Direct Data I/O (DDIO) [ 12 ]. For latency-sensitive 
applications like remote healthcare or autonomous driving, this linear 
increase is especially problematic. To reduce end-to-end latency, a 
number of research have concentrated on traffic scheduling, VNF ac -
celeration, resource utilization, and VNF instantiation. Although these 
works offer useful first insights, they frequently assume linear acceler -
ation and sequential execution of VNFs within a single SFC, which 
simplifies coordination but ignores potential parallelism among VNFs 
like Caching and NAT, which can function concurrently. Nearly half of 
VNF pairings can be processed concurrently without a precise sequence, 
according to empirical data [ 9 ]. Parallelized VNF placement has only 
been attempted by a few numbers of conventional techniques, with only 
modest performance gains under increasing SFC demands. Furthermore, 
in order to maximize p-SFC coordination, current methods typically rely 
on prior information and are unable to dynamically and intelligently 
capture hidden dependencies between VNFs or changeable network 
states.
Recent studies have investigated Network Function Parallelism 
(NFP), which enables certain VNFs to handle traffic concurrently rather 
than strictly sequentially, in order to overcome intrinsic sequential delay 
[ 13 ]. As seen in Fig. 1 , NFP can be used to lower latency for some VNFs 
that support parallel execution, like caching and NAT. In order to 
convert a serial/sequential SFC (s-SFC) into a parallelized SFC (p-SFC), 
NFP finds parallelizable VNF instances where packets can be processed 
concurrently, divides traffic among them, and merges outputs [ 14 ]. 
Shorter routing paths and lower end-to-end latency are made possible by 
deploying VNFs based on NFP. However, as NFP may result in increased 
memory usage, extra packet transmissions, traffic loads, and packet loss, 
the conversion of an s-SFC to a p-SFC must maintain overall SFC 
integrity. Even though NFP has the potential to reduce latency, current 
solutions frequently ignore two important factors: VNF sharing across 
numerous requests and resource allocation fairness. While ignoring VNF 
reuse during parallelization loses potential for increased resource effi -
ciency, ignoring fairness can result in resource monopolization [ 13 ]. 
Because numerous VNFs vying for shared server and link resources can 
raise processing latencies, lower performance, and possibly break Ser -
vice Level Agreements (SLAs), reducing end-to-end latency alone is 
insufficient for p-SFC implementations [ 14 ]. In order to handle more 
SFC requests and balance network performance, scalability, and stabil -
ity, a fairness-aware solution guarantees equal resource allocation while 
preserving latency limitations.
The SFC placement is generally an NP-hard problem, and Deep 
Reinforcement Learning (DRL) [ 15 – 17 ] has gained popularity due to its 
adaptability to dynamic environments. Nevertheless, computational 
cost and the extra resources required for packet replication and merging 
present difficulties for DRL solutions that include VNF sharing with NFP 
[ 18 ]. Furthermore, it is impossible to overlook erratic resource varia -
tions and traffic needs. Federated DRL (FDRL) [ 19 , 20 ], which integrates 
DRL and federated learning, has demonstrated encouraging results in a 
number of applications. FDRL is a promising method for SFC placement 
and coordination because neural networks in DRL and federated 
learning can learn correlations among VNFs, network states, and per -
formance rewards. However, model-based VNF placement learning en -
counters efficiency issues and increased resource usage as SFC counts 
and network state complexity rise. Current approaches, such as feder -
ated learning, are time-consuming and unable to dynamically take VNF 
independence into account for parallelized placement.
These challenges motivate the need for a unified framework that 
combines fairness, SFC parallelization, and VNF sharing. To address this 
issue, we propose the Fairness-aware and Parallelized SFC Placement 
with VNF Sharing (FPPVS) framework. FPPVS uses Federated Deep 
Reinforcement Learning (FDRL) to make adaptive placement decisions 
under dynamic network conditions. It converts sequential SFCs into 
partially parallel SFCs whenever dependencies allow, reducing end-to- 
end latency through concurrent VNF execution. At the same time, it 
reuses existing VNF instances whenever possible to reduce deployment 
cost and improve resource utilization. A fairness-aware resource allo -
cation strategy prevents a small number of SFCs from monopolizing 
network resources. FPPVS also decides which VNFs should run in par -
allel, which instances can be shared, and where new instances should be 
deployed while satisfying latency and resource constraints. Finally, the

The key contributions of this study are given below: 
• FPPVS is a novel SFC placement framework that simultaneously in -
tegrates fairness, NFP, and VNF sharing to optimize resource utili -
zation in MEC-enabled IoT networks. It transforms s-SFCs into 
partially parallelized structures for concurrent packet processing, 
strategically reuses existing VNFs to minimize overhead and latency, 
and employs fairness-aware resource allocation across networks to 
ensure efficient utilization while maintaining QoS and equitable 
service delivery.
• A FDRL framework is proposed to train a global model across or -
chestrators and the cloud using latency- and reward-based aggrega -
tion. SFCs are decomposed according to network resources and 
parallelizable VNF pairs for fast convergence, while VNF parallelism

methods through extensive simulations across several MEC-enabled 
IoT situations.

2. Related work
A wide spectrum of approaches has been investigated in the litera -
ture for the SFC placement problem, including evolutionary algorithms 
[ 21 , 22 ], hybrid models [ 23 ], clustering-based techniques [ 24 – 26 ], 
neural networks [ 27 , 28 ], and more recently, machine learning-based 
solutions [ 29 ]. This study classifies existing solutions into non-DRL 
and DRL-based approaches and summarizes the relevant literature. 
Table 1 summarizes related works.
2.1. Non-DRL approaches
Traditionally, the SFC placement problem has been formulated as a 
mathematical optimization task solvable by exact methods. While exact 
solvers can provide optimal solutions, their high computational cost 
limits their applicability in large-scale or dynamic networks. Heuristic 
and meta-heuristic methods, which provide near-optimal solutions with 
much lower complexity and quicker execution times, have been 
frequently used to overcome problem. Despite their effectiveness, these 
techniques frequently sacrifice optimality, and in dynamic, diverse 
contexts where scalability and flexibility are crucial, their performance 
may deteriorate [ 44 , 45 ].
Static SFC deployment and resource allocation were the main topics 
of early research. In order to guarantee dependability, Liu et al. [ 14 ] 
suggested a latency-minimization strategy in heterogeneous edge envi -
ronments by simultaneously optimizing SFC deployment and resource 
management. In order to enhance resource utilization and minimize the 
number of servers needed, Li et al. [ 46 ] created a correlation-based 
greedy method for mapping SFC requests to actual machines. In order 
to optimize p-SFC deployment, Zhang et al. [ 47 ] presented a dynamic 
programming methodology inspired by Viterbi, which resulted in 
reduced latency and effective resource usage when compared to con -
ventional greedy methods. In order to reduce VNF deployment costs, 
energy consumption, traffic forwarding costs, and SLA violations, Bari

A number of studies expanded SFC placement to take multi-domain 
settings, latency restrictions, and dependability into account. For NFV- 
enabled datacenter networks, Qu et al. [ 30 ] introduced a 
reliability-aware and latency-constrained (READ) routing system that 
uses the heuristic Greedy-k-shortest paths (GSP) algorithm to minimize 
end-to-end latency and maximize service reliability. In order to improve 
provider profit through VNF migration, reinstantiation, and reschedul -
ing while taking heterogeneous node resources and migration costs into 
account, Li et al. [ 50 ] investigated dynamic SFC mapping and sched -
uling in Internet of Vehicles (IoV) services and introduced Tabu 
Search-based methods. In their investigation of the relationship between 
resource consumption and SFC latency, Liu et al. [ 31 ] proposed a 
Discrete Spider Monkey Optimization (DSMO) approach to reduce 
overall network latency and formulated a joint VNF deployment and 
resource allocation problem as a linear programming model.
Specialized heuristics and orchestration techniques were investi -
gated in other investigations. While Fang et al. [ 51 ] enhanced SFC 
embedding through joint state and VNF orchestration, Asgarian et al. 
[ 52 ] addressed linearization of non-linear constraints to reach 
near-optimal solutions. Liu et al. [ 53 ] presented a Lagrangian relaxation 
heuristic for dynamic orchestration, improving latency performance and 
service acceptance, and Thanh et al. [ 54 ] suggested an energy-sensitive 
deployment technique for edge-cloud settings for IoT-specific situations. 
In their investigation of multi-provider Network Service Embedding 
(NSE), Dietrich et al. [ 32 ] showed notable reductions in service cost and 
resource consumption by breaking down the problem into SFC graph 
partitioning and mapping using ILPUsing a graph partitioning technique 
influenced by game theory, Leivadeas et al. [ 33 ] demonstrated the ex -
istence of a Nash equilibrium to meet server affinity, collocation, and 
latency restrictions for SFCs. EPSFC, a heuristic for the energy-efficient 
and latency-conscious deployment of p-SFCs in NFV networks, is pro -
posed by Chintapalli et al. [ 34 ]. It optimizes server and link utilization, 
ensures end-to-end latency while lowering energy consumption and 
allowing more PSFC queries, co-locates parallel VNFs, and dynamically 
distributes resources based on a resource–latency model. In order to 
achieve near-optimal deployment with lower latency, Luo et al. [ 35 ] 
present ParaSFC, a heuristic method that turns s-SFCs into parallelized 
configurations by utilizing VNF dependencies and the Viterbi dynamic 
programming algorithm to find bottlenecks and modify processing 
sequences.
A number of complimentary approaches to enhancing intelligent 
network service management have been identified by recent research. 
Through autonomous decision-making and fault prediction, adaptive 
predictive frameworks have been proposed to improve the reliability of 
large-scale distributed systems [ 55 ]. Memory-efficient packet process -
ing techniques have been implemented at the network infrastructure 
level to enhance scalability and lower processing overhead in 
high-speed multi-tenant networks [ 56 ]. Recent developments in mobile 
and edge environments have concentrated on DRL-based resource 
optimization under dynamic wireless situations [ 57 ], secure task off -
loading in vehicular edge computing [ 58 ], collaborative edge intelli -
gence for big AI models [ 59 ], and mobility-aware connectivity 
management [ 60 ].
Although these optimization- and heuristic-based approaches pro -
vide useful answers in specific situations, they are still not very flexible 
when applied to diverse, large-scale, and dynamic networks. While 
heuristic procedures frequently compromise optimality, especially as 
networks grow and SFC diversity rises, exact solutions are computa -
tionally impractical in complicated situations. These restrictions have 
spurred research into more flexible and learning-based approaches that 
can balance efficiency, scalability, and service quality while reacting 
dynamically to network changes.
2.2. DRL approaches
DRL has emerged as a potent technique for adaptive and intelligent 
resource allocation in the extensive research on the effective deploy -
ment of SFCs in networks allowed by MEC and NFV [ 44 , 45 ]. Compared 
to conventional static or rule-based approaches, DRL can efficiently 
capture dynamic network conditions and offer more scalable and 
effective placement techniques by continuously engaging with the 
network environment and learning from previous experiences.
DRL has been used in a number of studies to address different issues 
of SFC placement. With an emphasis on multi-agent learning to increase 
service provider profitability, Zahedi et al. [ 61 ] use DRL for dynamic 
SFC placement and resource allocation in fog and edge computing. A 
deep learning-based system for proactive scaling of VNF resources by 
forecasting processor, memory, and bandwidth demands is proposed by 
Taha et al. [ 62 ]. A DRL method based on an enhanced deep determin -
istic policy gradient is presented by Liu and Zhang [ 63 ], which achieves 
faster convergence and a latency reduction of more than 28%. In order 
to accommodate high-dimensional inputs, improve generalization, and 
prevent retraining in lower-dimensional settings, Zhou et al. [ 36 ] pre -
sent a similar zone Multi-Objective DRL (rzMODRL) architecture that 
uses an encoder-decoder Long Short-Term Memory (LSTM) model. In 
order to meet latency restrictions, Qu et al. [ 37 ] integrate traffic 
modeling with deep Q-learning to handle dynamic VNF scaling and 
migration under non-stationary traffic. Their method uses a fractional 
Brownian motion (fBm) traffic model, which allows for precise adap -
tation to traffic fluctuations by learning traffic parameters for each 
stationary segment of a non-stationary trace utilizing change point 
detection in conjunction with Gaussian Process Regression (GPR).
Other noteworthy DRL-based solutions concentrate on multi- 
objective and QoS-aware optimization. An online SFC deployment 
strategy that balances load, controls resource consumption, and gua -
rantees QoS for Internet of Things applications is proposed by Xu et al. 
[ 64 ] for cloud-edge collaborative architectures. The Autoscaling and 
Priority-aware SFC Deployment (APSD) framework, introduced by Yu 
et al. [ 38 ], uses an actor-critic DRL model to maximize acceptance rate, 
deployment cost, and service latency. Similar to this, Wang et al. [ 39 ]

In parallel, NFP has gained attention as a method to enhance SFC 
performance by enabling concurrent processing of VNFs. Huang et al. 
[ 41 ] propose the Parallel VNF Placement (PVFP) framework, which uses 
FDRL with three parallelism identification rules, partitions SFCs across 
multi-domain resources for balanced deployment, and trains a global 
model via latency- and reward-based federated aggregation. Building on 
similar principles, Guo and Rezaeipanah [ 42 ] develop the Distributed 
Parallel Chaining (DPC) algorithm, which simultaneously activates 
non-conflicting VNFs and employs the A3C framework to maximize 
cumulative rewards and improve resource utilization across distributed 
servers. The problem of high latency and variable resource demand in 
SFC deployment within MEC networks is addressed by Zhang et al. [ 43 ]. 
The Parallelizing VNFs under Resource Demand Uncertainty (PVRDU) 
framework is suggested by the authors. PVRDU assembles sub-SFCs 
using a DRL-based method and uses dependencies between VNFs to 
convert conventional s-SFCs into parallelized configurations. To further 
provide more dependable and low-latency SFC deployment, a 
Markov-based approximation approach is utilized to efficiently control 
resource demand uncertainty.
Despite these developments, there are still a number of difficulties 
with SFC placement based on DRL and NFP. Current DRL techniques 
frequently rely on Seq2Seq models that cannot effectively manage 
sequential dependencies, underuse graph-based neighborhood infor -
mation to represent network states, and suffer from error propagation 
because of VNF-by-VNF insertion. Although promising, NFP-based 
methods have computational overhead and complicated VNF de -
pendency management. The creation of frameworks that incorporate 
fairness, parallelism, and VNF sharing for more effective and scalable 
SFC placement is motivated by these constraints.

4. Proposed model
This section presents the suggested FPPVS model to solve the issue of 
SFC placement under NFP in MEC situations. After describing the VNF 
instance sharing module, we start by summarizing the fundamentals of 
SFC parallelization. We then give a thorough description of how an 
FDRL-based algorithm for the placement and assembly of SFC requests is 
configured and trained. The model seeks to accomplish a balanced trade- 
off between four major objectives: utility improvement, delay minimi -
zation, cost efficiency, and service acceptance maximization. It is guided 
by the specified objective function.
4.1. SFC parallelism principle
Managing the deployment and execution of SFCs that users request is 
the primary duty of an NFV orchestrator. As shown in Fig. 1 , s-SFCs can 
be converted into parallelized structures depicted as DAGs, which are 
made up of a primary chain and multiple auxiliary branch chains of 
VNFs, to improve efficiency and performance. At the egress node or an 
intermediary shaping function, each branch chain eventually rejoins the 
main chain.
Transforming an s-SFC into a p-SFC requires compliance with several 
principles [ 35 ]. In this process, each traffic flow is routed through the 
main chain, where it is processed by the VNFs deployed along it, while 
duplicate flows are simultaneously forwarded through the branch chains 
for complementary processing. The p-SFC's main chain must maintain 
the same modification vector in order to guarantee equivalency with the 
original s-SFC and the same functional results. Furthermore, while 
passive VNFs like monitors can function independently without 
compromising semantic integrity, dependency constraints among VNFs 
in the s-SFC must be strictly maintained in the parallelized structure. For 
example, a Packet Header Inspector (PHI) must always come before 
shaping functions or a Network Address Translator (NAT). This study 
makes the assumption that all dependency ties between VNFs are known 
prior to placement, in line with earlier research by Luo et al. [ 35 ].
Every VNF in an SFC can be categorized as either a shaper or a 
monitor. While shaper VNFs actively analyze and modify the traffic to 
impose particular network policies, monitor VNFs watch traffic flows 
without changing the packets. Branch chains with monitor or shaper 
VNFs eventually converge back into the main chain when building a p- 
SFC, either at the egress or at a shaper node. This structural arrangement 
guarantees that monitors offer visibility and analysis without compro -
mising the integrity of the traffic, while shapers carry out the required 
flow changes. Before applying the SFC deployment and routing process, 
Algorithm 1 is applied for parallelization. The proposed SFC paralleli -
zation algorithm converts an s-SFC into a p-SFC consisting of a main 
chain and multiple branch chains while preserving VNF dependencies 
and ensuring processing equivalency. The algorithm begins by initial -
izing the main chain with the ingress node, while the set of branch 
chains and outstanding monitor VNFs are kept empty. It then iterates 
through each VNF in the s-SFC: if the current VNF is a monitor, a new 
branch chain is created from the last VNF in the main chain to the 
monitor, which is also added to the outstanding set. If the VNF is a 
shaper, it is appended to the main chain, and any dependent monitors in 
the outstanding set are connected to it before being removed. At the end, 
the last VNF in the main chain is connected to the egress. While monitor 
VNFs are arranged into branches without changing flow semantics, this 
approach guarantees that shaper VNFs stay in order along the main 
chain, maintaining the modification vector of the original s-SFC. 
Furthermore, the technique guarantees that the final p-SFC retains 
complete functional correctness by rigorously maintaining dependency 
restrictions and removing superfluous placements.

4.2. VNF sharing
A VNF can be deployed in two alternative ways: by instantiating a 
new instance or by sharing an already initialized one [ 9 ]. Several prior 
works approach VNF placement by directly assigning each VNF to a 
node with the exact number of resources it demands. Precise resource 
allocation is often impractical under resource scarcity, and adding more 
VNFs can increase hop-counts in the MEC topology, reducing placement 
efficiency. Whether to reuse an existing instance and which instance to 
choose are two crucial choices for effective reuse. Predicting future VNF 
requests is much more difficult with online SFC placement since each 
allocation affects future SFC routing. Thus, a crucial and difficult part of 
effective online SFC placement is figuring out when and when to reuse 
VNF instances.
Inspired by [ 5 , 13 , 42 , 47 ], FPPVS integrates an instance sharing 
module that decides how VNFs are deployed in order to maximize 
resource consumption. In order to help the agent choose suitable hosts 
for freshly initiated instances, FPPVS uses a queuing network to record 
the distribution of VNFs. An LSTM module and a SQN memory make up 
the SFC Queue Network (SQN), which is intended to record and forecast 
the temporal distribution of necessary VNFs. In the meantime, the 
time-depth (TD) option determines the length of the SQN memory, 
which is organized as a tiered queue that holds previously needed VNFs. 
A trade-off between minimizing computing cost and capturing adequate 
temporal correlations is used to choose the TD parameter in the queuing 
network.

parts of the SQN's detailed design, which is shown in Fig. 2 . The SQN 
memory is organized as a layered queue, where each layer represents the 
computing resources required by a specific SFC request u , denoted as φ
u
.

The suggested FPPVS framework includes an FDRL module to deploy 
the generated sub-SFCs in parallel. Each sub-SFC's placement is designed 
as a Markov Decision Process (MDP) [ 47 ], allowing the agent to 
continuously interact with the network environment and discover the 
best placement strategy. Convolutional Neural Networks (CNNs) are 
used to implement both the actor and the critic in the FDRL agent's 
actor-critic architecture. A fully connected layer with 256 neurons 
comes after three convolutional layers with a kernel size of 3 × 3, each of 
which has 64 filters and ReLU (Rectified Linear Unit) activation func -
tions. While the critic network assesses the corresponding state values to 
direct policy optimization, the actor network outputs the probability 
distribution over possible placement actions. Batch normalization is 
used following each convolutional layer to increase training stability 
and speed convergence. Additionally, a dropout layer with a rate of 0.3 
is used to reduce overfitting and improve the learnt model's capacity for 
generalization. Mini-batches of 128 samples are used for gradient up -
dates during the learning process, and the networks are trained using the 
Adam optimizer with a learning rate of 0.0005. Fig. 3 depicts the 
actor-critic-based FDRL algorithm's design.

5. Performance evaluation
We do a comprehensive study including several facets of SFC 
placement and orchestration in order to evaluate the performance of the 
suggested approach. The simulation setup, network topologies, baseline 
DRL methods for comparison, ablation analysis of framework compo -
nents, and simulation results comprise the five sections of this section.
5.1. Simulation setup
The simulation environment used to assess the suggested model is 
described in this section. In order to ensure compatibility with estab -
lished benchmarks, computational capacity for both VNFs and edge 
servers are obtained from previous studies [ 9 , 47 ]. Node capacities are 
uniformly distributed between 10 and 20 units, while link bandwidths 
range from 100 to 200 units with increments of 20, and link latencies are 
uniformly set between 5 and 20 units [ 13 , 42 ]. The processing cost per 
unit of computational resource is assumed to be $0.001 per hour.
In this study, simulations are performed for 4000 SFC requests. 
Traffic demands for each SFC request follow a power-law distribution 5 
to 30, reflecting the heavy-tailed nature of task loads in edge computing 
scenarios, where a small fraction of requests accounts for most of the 
load while the majority exhibit moderate demand [ 6 , 47 ]. Maximum 
tolerable latencies for requests are sampled uniformly within 100 to 150 
ms, and initial packet sizes are drawn from a uniform distribution of 50 
to 100 packets. Each SFC request is assigned a service lifetime sampled 
from an exponential distribution with a mean of 1000 time units, while 
SLA latency requirements are uniformly distributed between 2- and 
4-time units. The auxiliary VNFs representing the source and destination 
of the SFC are independently mapped to randomly selected DCs [ 42 , 68 ]. 
Each SFC consists of 4 to 10 VNFs, selected from five distinct types — IDS, 
DPI, LB, FW, and NAT — each with heterogeneous resource demands [ 1 ,
6 ]. The computational resources required for VNF instantiation follow a 
uniform distribution of 500 – 900 Mbps, processing latencies per data 
unit are set uniformly between 0.01 and 0.2 ms, and the per-link 
bandwidth requirement for each VNF ranges from 20 to 100 units.
Agents are trained in batch mode over 2000 iterations. In each 
iteration, the agent interacts with the environment over 10 episodes, 
each involving the placement of 20 SFCs, to populate its experience 
Q. Zhu et al.                                                                                                                                                                                                                                     Computer Networks 290 (2026) 112774 
11 \nbuffer. The collected experiences are then used to update the agent ’ s 
parameters in batch. Both the environment and buffer are reset after 
each iteration, reflecting an on-policy training methodology. The Adam 
optimizer is employed, with actor and critic learning rates set to 0.00001 
and 0.0001, respectively [ 35 ]. All simulation modules and agents are 
implemented in MATLAB. Experiments are executed on a Windows 11 
workstation equipped with a 4.1 GHz Intel Core i7 processor and 32 GB 
of RAM. Each experiment is repeated 25 times, and the reported results 
represent the average performance across these runs.
5.2. Network topologies
The proposed model is evaluated in two backbone and metropolitan 
network scenarios [ 9 ]. For the backbone case, we use the USAnet to -
pology shown in Fig. 4 (a), consisting of 24 switches and 47 links. For the 
metropolitan scenario, we consider the access network of an Italian 
mobile operator, which interconnects 17 mobile traffic aggregation 
nodes to a Serving Gateway via 29 links, as illustrated in Fig. 4 (b). All 
nodes in both topologies are capable of deploying a VNF server.
5.3. Baselines methods
To evaluate the performance of the proposed FPPVS model, we 
selected four representative state-of-the-art methods as baselines: RVNF 
[ 40 ], DRL-SFCP [ 39 ], PVFP [ 41 ], and DPC [ 42 ]. RVNF focuses on 
DRL-based VNF reuse, DRL-SFCP leverages DRL with GCN and Seq2Seq 
models to optimize SFC placement for maximizing long-term revenue, 
PVFP emphasizes cost-efficient VNF placement, and DPC activates 
non-conflicting VNFs in parallel using A3C to maximize cumulative re -
wards and enhance resource utilization. These methods were chosen 
because they collectively cover a broad spectrum of SFC placement 
strategies, including DRL-based dynamic VNF placement, p-SFC execu -
tion, predictive VNF provisioning, and enhanced SFC placement heu -
ristics. All baseline methods were either re-implemented according to 
their descriptions in the respective papers or executed using publicly 
available code to ensure correctness and reproducibility. Meanwhile, to 
guarantee a fair and consistent comparison, all experiments were con -
ducted under identical assumptions, network topologies, and parameter 
configurations. This includes the same resource capacities, link char -
acteristics, SFC request distributions, and simulation settings.

The additional complexity introduced by FPPVS is justified by its 
overall performance gains. Although the complete framework requires 
only a 9.2% longer execution time than RVNF, it consistently achieves 
higher service acceptance, better resource utilization, higher 
throughput, and shorter SFC assembly paths across both network to -
pologies. Furthermore, its execution time remains lower than that of 
DRL-SFCP, PVFP, and DPC. It is worth noting that the reported execution 
time includes the computational overhead introduced by the FDRL 
framework, including local model training, periodic model aggregation, 
synchronization, and parameter exchange with the central server. Since 
federated aggregation is performed periodically rather than after every 
placement decision, and only model parameters are exchanged instead 
of raw data, the communication and synchronization overhead remains 
limited. Consequently, the additional cost introduced by federated 
learning is modest and is compensated by the improvements in scal -
ability and placement quality.
Fig. 6 reports the results when SFC requests arrive sequentially, 
whereas Fig. 7 shows the cumulative rewards when requests are pro -
cessed in batches of 100 concurrent SFC requests. The request processing 
approach is the primary cause of the various reward trends. The network 
still has enough resources when there are few SFC requests, and there is 
little rivalry amongst requests. Consequently, all approaches yield 
comparable outcomes. For instance, Fig. 6 shows that PVFP's perfor -
mance is fairly similar to FPPVS's before about 500 queries. The per -
formance disparity becomes increasingly noticeable as the demand 
grows. Because FPPVS blends fairness-aware resource allocation with 
VNF instance sharing, it retains larger cumulative rewards. These two 
strategies balance resource utilization, cut down on pointless de -
ployments, and maintain a steadier learning process even in the face of 
high traffic. RVNF and DRL-SFCP, on the other hand, often create new 
VNF instances when resources are available and primarily rely on 
shortest-path placement. While this approach works rather well at low 
traffic loads, as the network gets more crowded, it eventually results in 
resource fragmentation and decreased rewards. Additionally, DPC re -
ceives less cumulative rewards, particularly in the early stages of 
learning. Its heuristic approach prioritizes lowering resource and energy 
consumption, which restricts throughput and lowers reward increase. 
Because both approaches are based on FDRL, the comparison with PVFP 
is very intriguing. Nevertheless, PVFP continues to generate new VNF 
instances more frequently, which raises deployment overhead.

The proposed framework does not improve performance by simply 
deploying more VNF instances. When an SFC is parallelized, the agent 
first tries to reuse existing VNF instances. A new instance is created only 
if no suitable shared instance is available. This keeps the overhead of 
parallelization low. The reward function also encourages VNF sharing 
and discourages unnecessary instantiations. In addition, the placement 
policy considers the available resources in each domain and avoids 
unnecessary traffic and inter-domain communication. As a result, FPPVS 
reduces end-to-end latency while using fewer VNF instances and less 
bandwidth. These gains come from smarter resource management and 
VNF reuse, not from creating extra network resources.
6. Conclusions
This paper proposed FPPVS, a fairness-aware framework for efficient 
SFC placement in MEC-enabled IoT networks. The framework combines 
SFC parallelization, VNF instance sharing, and federated deep rein -
forcement learning to improve deployment efficiency. The paralleliza -
tion module converts sequential SFCs into partially parallel structures, 
allowing independent VNFs to run simultaneously and reducing end-to- 
end latency. The VNF sharing module reuses existing instances when -
ever possible and employs LSTM-based demand prediction to reduce 
deployment overhead and improve resource utilization. A fairness- 
aware allocation strategy balances network resources among 
competing SFC requests while maintaining QoS requirements. The 
FDRL-based placement engine enables distributed agents to learn 
collaboratively and adapt to changing network conditions. Experimental 
results show that FPPVS consistently improves service acceptance, 
resource utilization, throughput, and fairness while reducing latency 
compared with existing methods. Future work will investigate energy- 
aware placement, collaborative optimization with caching and task 
offloading, and more robust deployment under highly dynamic network 
conditions.
